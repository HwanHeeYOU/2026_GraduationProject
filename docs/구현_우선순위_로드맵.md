## 1단계 — 빠른 완성 (쉬움, 독립적)

### 1. 프로젝트 이름 수정 UI
- **무엇**: 대시보드 또는 워크스페이스에서 프로젝트명 인라인 편집
- **왜 먼저**: API(`PATCH /api/projects/[id]`)가 이미 구현되어 있어 UI만 추가하면 됨
- **관련 파일**: `components/dashboard/ProjectCard.tsx`
- **구현 포인트**: 프로젝트 이름 클릭 → `<input>` 전환 → blur/Enter 시 PATCH 호출

### 2. 모듈 작성 진행률 표시
- **무엇**: 워크스페이스 상단에 "7 / 10 항목 작성 완료" 형태의 프로그레스 바
- **왜 먼저**: `content`가 비어있는 `ProjectModule` 수를 세면 되므로 로직 단순
- **관련 파일**: `components/workspace/WorkspaceClient.tsx`
- **구현 포인트**: `modules.filter(m => m.content?.trim()).length` / `modules.length`

### 3. 환경변수 유출 방지 확인
- **무엇**: `.env.local`이 `.gitignore`에 포함되어 있는지 확인, gitleaks 도입 고려
- **왜 먼저**: 코드 변경 없이 설정 확인만으로 완료 가능
- **관련 파일**: `.gitignore`
- **구현 포인트**: `.env*.local` 패턴이 `.gitignore`에 있는지 확인

### 4. NEXTAUTH_SECRET 강도 검증
- **무엇**: 프로덕션 배포 시 강한 시크릿 사용 여부 문서화
- **왜 먼저**: `openssl rand -base64 32` 실행 후 `.env.production`에 적용, 즉시 완료
- **관련 파일**: `.env.local`, `.env.production`

## 2단계 — 보안 강화 (보통 난이도, 독립적)

### 5. 파일 업로드 보안 강화
- **무엇**: 업로드 파일의 실제 MIME 타입을 서버에서 검증해 악성 파일 차단
- **관련 파일**: `app/api/ai/analyze-irb-file/route.ts`
- **구현 포인트**: `file-type` 라이브러리 설치 → 확장자가 아닌 실제 바이너리 시그니처 검증
  ```ts
  import { fileTypeFromBuffer } from 'file-type'
  const type = await fileTypeFromBuffer(buffer)
  if (!['application/pdf', 'application/vnd.openxmlformats-officedocument.wordprocessingml.document'].includes(type?.mime ?? '')) {
    return NextResponse.json({ error: '허용되지 않는 파일 형식' }, { status: 400 })
  }
  ```

### 6. Rate Limiting (AI API)
- **무엇**: AI 엔드포인트에 사용자별 분당 요청 횟수 제한
- **관련 파일**: `app/api/ai/generate/route.ts`, `app/api/ai/analyze-irb-file/route.ts`
- **구현 포인트**: `upstash/ratelimit` 또는 인메모리 Map으로 구현
  - 분당 10회 제한 권장
  - 초과 시 `429 Too Many Requests` 반환

## 3단계 — 핵심 기능 완성 (보통 난이도, 독립적)

### 7. PDF 한글 폰트 처리 개선
- **무엇**: PDF 생성 시 한글이 깨지지 않도록 나눔고딕 등 폰트 임베드
- **관련 파일**: `lib/export/generatePdf.ts`, `public/fonts/`
- **구현 포인트 (2가지 옵션)**:
  - **옵션 A**: `jspdf`에 나눔고딕 Base64 폰트 `addFont()`로 등록
  - **옵션 B**: `@react-pdf/renderer`로 라이브러리 교체 (품질 높음, 마이그레이션 비용 있음)
- **권장**: 옵션 B — 장기적으로 미리보기 기능(`#내보내기 미리보기`)도 함께 해결됨

### 8. 작성된 내용 AI 검토 / 피드백
- **무엇**: 각 모듈 내용을 Claude가 읽고 IRB 기준 충족 여부·보완 사항을 코멘트로 제시
- **관련 파일 (신규)**: `app/api/ai/review/route.ts`
- **관련 파일 (수정)**: `components/workspace/ModuleCard.tsx`
- **구현 포인트**:
  - AI 초안 생성 버튼과 **별도 버튼**으로 구현 ("AI 검토 요청")
  - 응답은 코멘트 형태로 카드 하단에 표시
  - 프롬프트 예시: `"다음 IRB 항목 내용을 검토하고 부족한 점과 보완 제안을 한국어로 3가지 제시해줘"`

## 4단계 — 사용자 계정 기능 (외부 서비스 연동 필요)

### 9. 비밀번호 찾기 / 재설정
- **무엇**: 이메일로 재설정 링크 발송, 토큰 기반 비밀번호 변경
- **관련 파일 (신규)**: `app/auth/forgot-password/page.tsx`, `app/api/auth/reset-password/route.ts`
- **구현 포인트**:
  1. `prisma/schema.prisma`에 `PasswordResetToken` 모델 추가
  2. Resend(resend.com) 또는 Nodemailer + Gmail SMTP 연동
  3. 토큰 만료 시간 1시간 설정
- **선행 작업**: Resend API 키 발급 또는 Gmail App Password 설정

## 5단계 — 관리자 기능 (의존성 있음, 순서 중요)

### 10. 관리자 역할(Role) 구분 ← 먼저 완료해야 11~13이 가능
- **무엇**: `User` 모델에 `role: ADMIN | USER` 추가, 관리자 페이지 접근 제어
- **관련 파일**: `prisma/schema.prisma`, `lib/auth.ts`, `middleware.ts`
- **구현 포인트**:
  ```prisma
  enum Role { USER ADMIN }
  model User {
    role  Role  @default(USER)
    ...
  }
  ```
  - `middleware.ts`에서 `/admin/**` 경로는 `role === ADMIN`만 통과

### 11. 기관 관리 CRUD (관리자)
- **무엇**: 관리자 UI에서 기관 추가·수정·삭제 (현재는 seed.ts 직접 수정만 가능)
- **관련 파일 (신규)**: `app/admin/institutions/page.tsx`, `app/api/admin/institutions/route.ts`
- **선행 조건**: #10 완료

### 12. IRB 모듈 관리 CRUD (관리자)

- **관련 파일 (신규)**: `app/admin/modules/page.tsx`, `app/api/admin/modules/route.ts`
- **선행 조건**: #10 완료

### 13. 기관 추가 UI

## 6단계 — 배포 전 완료 (인프라)

### 14. SQLite → PostgreSQL 마이그레이션
- **무엇**: 프로덕션 환경에서 동시성·안정성을 위해 PostgreSQL로 전환
- **관련 파일**: `prisma/schema.prisma`, `.env.production`
- **구현 포인트**:
  ```prisma
  datasource db {
    provider = "postgresql"
    url      = env("DATABASE_URL")
  }
  ```
  - Railway / Supabase / Neon 중 하나 선택 권장
  - `npx prisma migrate deploy` 후 `npm run db:seed`로 초기 데이터 재삽입
